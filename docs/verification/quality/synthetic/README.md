# 合成语料（编造的会议）

这个目录里的东西**全部是编的**：一场虚构的「星桥书店会员体系改版评审会」。
没有客户名、没有公司内部规划、没有真人，所以它可以进仓库 —— 而这正是它存在的理由。

## 为什么要它

真实评测集在 `../cases/` `../runs/`，是从真实会议导出的逐字稿，**必须** gitignore。
代价是 CI 拿不到素材，「段数回退」「空话复现」这类退化就没人拦。

阶段 3-2 的验收标准就是这一条：**CI 能拦住这两类退化**。合成语料就是给它当靶子的。

## 它**不**测什么（写清楚，免得被读成「CI 绿 = 内容好」）

- **不测模型质量**。这里的 `runs/` 是手写的，不是模型跑出来的。
  模型好不好，只能在本地用真实语料跑（`Scripts/quality_report.sh --run --diff`）和用裁判打分
  （`--judge`）。
- **不测产品界面**。界面有另外的验证纪律。
- 它测的是**尺子本身**：同一份输入经指标代码算出来，该达标的还达标、该未达的还判未达、
  该「不可算」的不许拿 0 冒充。

所以「CI 绿」只说明**度量没有失真**，不说明纪要写得好。这两件事必须分开说。

## 一个 case 只放一个病症

每个 case 只偏离正常一处，其余指标全部健康。这样门禁亮的时候，
**能直接指出是哪一条指标坏了**，而不是「一锅粥里有东西不对」。

| case | 期望 | 病症 | 钉住什么 |
|---|---|---|---|
| `syn-good` | 有内容 | 无（下限基线） | 任何一条变未达，都是口径或清洗被改坏了 |
| `syn-repeat-storm` | 有内容 | 22 段/分钟但清洗没折叠 | **段数回退**（`segmentRatioJudged`） |
| `syn-empty-talk-ritual` | 有内容 | 纪要开头「本次会议围绕X展开」 | 空话**句式表**（起兴句） |
| `syn-empty-talk-plain` | 有内容 | 纪要里有「会上介绍了…」 | 空话**裸词表** |
| `syn-meta-comment` | 走空态 | 材料不足却写了一段解释自己为什么写不出来 | P1-5 门禁（元评论） |
| `syn-clean-empty` | 走空态 | 无（正确行为） | 干净空态不被误判 |
| `syn-old-record` | 有内容 | 2A 之前的存盘结构：没有 `owner`、没有 `overviewBullets` 键 | **「不可算」不许被 0 顶替** |

空话为什么拆成两个 case：检测有**两套机制**（裸词表 + 句式表）。一个 case 里塞两种，
删掉其中一套时另一套还能抓到，门禁不会亮 —— 那就等于没覆盖。

## 谁在用

- CI：`.github/workflows/quality.yml` 的 `metrics` 任务跑
  `python3 Scripts/quality_report.py --corpus docs/verification/quality/synthetic --check`
- 本地：`Scripts/quality_report.sh --check`（或 `--synthetic` 只看报告）
- 反向证伪：`Scripts/tests/test_quality_report.py` 里的 `GateItselfBites`
  把七种已知退化逐个塞回代码，要求门禁真的变红 —— 只断言「门禁是绿的」不够，
  一个永远返回 0 的检查也是绿的。

## 改这里的规矩

改 `cases/` 或 `runs/` 之后，必须同步改 `expectations.json`；漏了会直接报
「×× 没有写进 expectations.json」。`--check` 拿到的判定与期望不一致就以退出码 1 结束。

加新 case 时先问一句：**这个 case 亮的时候，我能说出是哪条指标坏了吗？**
说不出就是病症不够单一，拆开。
