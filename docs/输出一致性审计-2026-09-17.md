# 输出一致性审计：转写方式 / 速览 / 纪要 是不是同一套

> **起因**：2026-09-17 提出 —— 「每一个录音 / 导入录音文件后，转写的方式、速览 + 纪要的
> 输出内容模板和样式以及内容风格，都一样的吗？作为一个专业软件，必须保持同样的内容风格成果。」
> 参照物：ima 的三个功能（实时录音 / 导入 / 其他入口）**共用一套内容模板与风格**。
>
> **本文只回答一件事**：整条链路里，哪些地方按"来源"分叉、哪些地方不分叉。
> 判定单位是**层**，不是"轮次"；每一层给证据，不给印象。

---

## 0. 一句话判定

**模板、提示词、解析、渲染：全链路只有一套，不按来源分叉。**

唯一的来源差异是 **「这份录音有没有说话人数据」**（录音双路有、导入没有）——
那是**数据可用性**差异，不是两套模板。它由同一段代码消费，不产生第二套输出结构。

但审计**确证了两处真正的不一致**，都不在"录音 vs 导入"这条轴上：

| 编号 | 不一致是什么 | 严重度 | 处置 |
|---|---|---|---|
| **D-1** | 「写清归属」这条指令**从来没有到达产出速览与纪要的那一步** —— 它只被拼进了**分章**那一步的 prompt，而分章是中间产物。长会与短会、录音与导入，用户看到的速览/纪要靠的都是模型自觉 | **高**（这是 P2-2a 双声道的**目的本身**） | **已修** |
| **D-3** | 标题从**清洗前**的段落里截，而正文用清洗后的段落 → 标题可能是用户没在界面上见过的碎句 | 中 | **已修** |
| **D-2** | 标题口径：导入取文件名，录音取「会议 + 前 24 字」 | 低（**有意**） | 保留，写明理由（§4） |

## 1. 判定方法

「一样的吗」这个问题，靠读一遍代码回答不了 —— 会漏掉"某一步被顺手写在别处"。
所以用一条**可检索的判据**：`captureMode` 是这场会话唯一的来源标识，
**它出现在哪里，来源就在哪里起作用**。全仓库检索（非 BRE，避开 `\|` 静默失效）：

```
grep -rnE "captureMode" --include="*.swift" .
```

命中分三类，**没有第四类**：

| 出现处 | 作用 | 是否影响输出内容 |
|---|---|---|
| `MeetingStore.swift:343` | `switch session.captureMode` 决定喂哪路音频、带不带双声道 | **是**（但只是"喂什么"，不是"怎么整理"） |
| `MeetingStore.swift:2080 / 2176` | 回放取哪个文件、导入的默认文件名 | 否 |
| `MeetingStore.swift:2176`、`WorkbenchView.swift:2666` | 标题来源、状态条副标题「已有音频 / 系统声音与 Mac 麦克风」 | 是（标题，见 D-2） |

**`SummaryEngine.swift` 里零命中**，`TranscriptCleaner.swift` 零命中，
`MeetingExport.swift` 零命中，速览 / 纪要 / 原文三页的渲染代码零命中。
—— 这句话就是 §2 整张表的依据。

## 3. 确证的不一致

### D-1 「写清归属」从来没有到达产出速览 / 纪要的那一步 —— **已修**

**事实**：`TranscriptSpeaker.materialLegend`（那段"凡原文标了说话人：结论、决策与待办都要写清归属"）
在改动前只被拼进 **`summarizeChapters`** 的 prompt 一处。

**为什么这是问题**（不是"只在分章给也够用"）：

1. 分章是**中间产物**。它的输出是章节摘要，只喂给后面的综合步骤；用户永远看不到它。
2. 真正产出速览 / 纪要的是 `requestStructuredFacts` 与 `requestMinutesText`。
   改动前这两段 prompt 里，**只有术语约束，没有归属要求**。
3. 当时代码注释给的理由是「分章是唯一看得见原文的一步」——
   **这对长会成立，对短会不成立**：`analyze` 里 `transcript.count <= 24_000` 时
   走的是**直接路径**，那一步拿到的**就是**带 `[我方]/[对方]` 的原文
   （`materialLine` 带前缀，`makeTranscript` 只是把它们 join 起来）。
   而本项目实测的典型材料是 1.6 万字 —— **大多数会议走的都是这条路**。

**后果**：双声道把跨方指代变得可判定之后，没有人告诉模型"可以判定了"，
于是它照旧写"会上讨论了"。这正是 `materialLegend` 自己的注释里写的那句话的反面：
「必须同时告诉模型"可以判定了"，否则它还是照旧写"会上讨论了"」。

**修法**（拆开 + 收口 + 单测，不是"记得改三处"）：

| 改动 | 为什么 |
|---|---|
| `materialLegend` 拆成 `materialMarkerExplanation`（标记是什么）+ `speakerAttributionDirective`（要求写归属） | 两块**适用条件不同**，合在一起就没法只给其中一块 |
| `materialLegend` 改成两块的拼接（**不是第三份文案**） | 分章那一步用它，必须与拆分前**逐字相同**（它已经跑在生产上） |
| 新增 `MeetingSummaryEngine.directives(terminology:markerExplanation:attribution:)` | 三处 prompt 的指令块**只有这一处实现** |
| 新增 `chapterDirectives` / `analysisDirectives` 两个静态纯函数 | 把"哪一步给哪一块"这条**容易搞反**的规则抽出来，可单测 |
| 归属要求：`hasSpeakers` 就给（与材料形态无关）；标记解释：只有源材料**是原文**时给 | 长会综合那一步拿到的是章节摘要、里面没有标记，对没有标记的材料解释标记 = 塞假信息 |
| 新增 `[TranscriptSegment].hasSpeakerLabels` | 「有没有说话人」这个判据改动前在 `summarizeChapters` 里就地写过一次，现在要用于第二处 → 按项目纪律抽成一处 |

**对导入路径的影响：零。** 导入的会议 `hasSpeakers == false` 且术语表为空时，
指令块是**空串** —— 两段 prompt 与改动前逐字相同。这条有机器判据
（`testBothStagesSayNothingAboutSpeakersWhenTheMeetingHasNone`），不是靠人工比对。

**效果未实测**，理由见 §5。

### D-3 标题从"清洗前"的段落里截 —— **已修**

`process()` 里 `session.title = MeetingAnalysisBuilder.title(for: session, segments: cleanedSegments)`。
改动前传的是 `segments`（清洗前的分块）。清洗会把一屏几十条 15 字的碎行合成正常句子，
所以标题可能是从一句**用户根本没在界面上见过**的碎句里截的，而下面正文里找不到那句话。
同一屏里两处对不上，用户只会以为软件在乱起名。**已改为与正文同一份材料。**

### D-2 标题口径：导入用文件名、录音用「会议 + 前 24 字」 —— **有意保留**

见 §4。

## 4. 有意保留的差异（写在这里，免得将来被人"顺手统一"掉）

| 差异 | 理由 |
|---|---|
| 导入的会议，速览 / 纪要里**不会**出现「我方 / 对方」 | 数据里就没有。**绝不替它猜一个说话人** —— 猜错的说话人是本项目最怕的那类"看不见的数据损坏"（读起来完全自然，永远没人发现） |
| 导入用**文件名**当标题，录音用「会议 + 概述前 24 字」 | 录音没有文件名可用；而导入的用户**自己起的文件名**比他三十秒后忘了的一场会更好认。统一成任一种都会让另一路变差 |
| 本地兜底整理**永不填 `owner`** | 规则匹配产不出可信的责任人；本项目已判定「让模型推断责任人」天花板只有 22.9%，硬推只会编造 |
| 材料不足 / 整理失败走另一套页面（空态、横幅） | 那是**状态**差异，不是**来源**差异：导入一场 25 秒的音频同样会进空态 |
| 老会话没有 `headline` / 要点 / 待确认 | 2A 之前存盘的数据里没有这几个键，`decodeIfPresent` 让它们消失 → 页面退化回升级前那一版，而不是一屏空白 |
| 录音用的两路音频是**分开**转的，句子切分与单路不同 | 每一路各自的静音判断不同。这是双声道能给出说话人标注的代价，已由 `TranscriptMerger` 按时间合并处理 |

## 4.5 外部对照：与 ima（腾讯）三页的并排比对

用户提供了一组参考截图（ima 里一场 20:39 的会议，2026-09-08 17:49），
原图存在 `docs/reference/ima-2026-09/`（`ima-原文.png` / `ima-速览.png` / `ima-纪要.png`）。

**先回答"他们三个功能是不是一套"**：是。三个 Tab 共用同一套排版语言（同一标题层级、
同一个项目符号样式、同一种书面语域）、同一条常驻播放器、都由一段总述开门。
这一点我们**同样成立**——见 §2，我们的三页也是同一套模板由字段驱动。

**再看形态取向的差别**（这才是真正值得看的地方）：

| 页 | ima | 我们（MeetingScribe） |
|---|---|---|
| 原文 | **段落级**：一段几百字连排，只标起止时间（00:00 / 00:48 / 01:34…），**没有说话人** | **行级**：一句一行，每句带时间戳，带 `[我方] / [对方]` |
| 速览 | **时间锚 + 小标题 + 连续叙述段**，按时间推进（`00:00 知识库与工单底座价值` + 一段话） | **清单体**：结论 → 要点 → 决策摘要 → 待办摘要 → 待确认 → 概述 → 经过，按信息类型分组 |
| 纪要 | **成文文档**：一段总述 + 主题分节（加粗小标题）+ 项目符号（`**知识沉淀与工单价值**：…`），**无时间戳** | **三组清单**：决策 / 待办 / 时间线，**带时间锚** |

**读出来的取向差异**：

- ima 面向**通读与呈送**——它的「纪要」是一篇可以直接转发给人看的文档。
- 我们面向**核对与执行**——逐字稿可跳回放、时间锚处处可点、待办可勾走。
- 两边各自内部都是**一套**，所以本题（"不同入口产出是否同一套"）两边都过关。

**我们的真实缺口（唯一一处）**：**纪要页缺"成文"这一形态**。
它现在是三组清单，不是一篇纪要。如果"产出要能拿得出手"是目标，
**纪要页是唯一值得再投的地方**（把决策/待办/时间线收成一篇有总述、有主题分节的文档），
而不是去改速览或原文。

**明确不照抄的两处**（避免下次有人"对齐竞品"顺手改坏）：

| 不抄 | 理由 |
|---|---|
| ima 的原文是**段落级**、不分行 | 会直接丢掉我们的核心能力：每句跳回放、逐字核对。可读性换可核对性，本产品不换 |
| ima 没有说话人标注 | 它没有说话人数据；我们双声道有。**有而不写**才是缺陷，`[我方]/[对方]` 正是 D-1 要送去 prompt 的东西 |

> 口径说明：以上只基于**三张截图、一场会**，不足以推断 ima 的全貌
> （不同长度会议、不同入口是否分叉，未验证）。当参考用，不当结论用。

## 5. 未实测 / 不可自动验证

1. **D-1 的效果无法量化。** 现有评测集 `docs/verification/quality/cases/*.json` 里，
   每个用例的 `segments` 只有 `start/end/text/confidence` —— **没有 `speaker` 字段**。
   也就是说：`actionsWithOwnerRatio` 这个指标**在当前评测集上不可能因为本次改动而动**。
   要量它，需要一份**带说话人**的素材，而双路真实音频本机造不出来
   （同一个卡点：`docs/质量提升执行计划.md` 的阶段 5-1 人工外放自测）。
   → **本次改动只做到「接线正确 + 有机器判据」，效果留待那份素材。**
2. **"两份 prompt 是同一套"验的是构造，不是模型行为。** 单测证明两段拿到**同一份**指令块、
   且没有说话人时与改动前逐字相同；它不能证明模型一定会照做。
3. 分章那一步的 prompt 在**指令块为空**时会少掉一个空行（`\(a)\n\(b)` 变成 `\(拼接结果)`）。
   对模型语义无影响，但**不是逐字节相同** —— 如实记在这里，不当成"完全没动"。
