# 状态表（权威条目）

> 建立于 2026-09-15（升级计划阶段 0）。
> **本表是「App 能进入的状态」的唯一权威副本**；`未解决问题与正确做法.md`（24 章）自本表建立起降级为**细节与证据来源**。
>
> **唯一判据**：任何时刻，用户看屏幕都能回答三件事 —— **现在在干嘛 / 下一步会发生什么 / 卡住该点哪。**
>
> **维护纪律**
> 1. 只放判据（显示什么字 / 能点什么 / 点了去哪），不放过程、不放历史。
> 2. **表要能一屏读完**（约 ≤ 24 行）。新增状态必须先落到本表，再写代码。
> 3. 表格里带 ⚠️ 的格子 = **当前说不清 / 有缺口**，就是后续阶段要改的点。改完把 ⚠️ 去掉。
> 4. 本表**不新增「轮次」**。

### F 组 · 把结果拿走（v0.11 新增 · **瞬时状态**）

**为什么单开一组**：上面 A~E 是**常驻状态**（判据是「现在在干嘛 / 下一步会发生什么 / 卡住该点哪」），
F 组是**瞬时状态**（判据只有「刚才那一下成没成」），它们不改变屏幕能做什么。
分开放，是为了让 A~E 那 22 行仍然能一屏读完。

| # | 状态 | 显示什么字 | 能点什么 | 点了变成 |
|---|---|---|---|---|
| **F1** | 导出面板已打开 | 系统保存面板：标题 `导出会议纪要`；说明 `导出为 Markdown：粘进飞书文档、腾讯文档、Notion 都能直接识别标题与列表。`；文件名预填 `<日期>-<标题>.md`；按钮 `导出` / `取消` | 面板内改位置、`导出`、`取消` | F2 / F3 / F4 |
| **F2** | 导出成功 | **一个字都不显示**（`exportNotice = nil`）。刻意为之：写文件是用户自己发起、位置也是他自己选的，成功再打扰一次是噪音。判据＝文件真的出现在那个位置 | — | 停在 C* |
| **F3** | 导出取消 | **无提示、不写日志**（`.cancel` 直接 return）。「主动取消」与「写入失败」必须分开 —— 混成同一件事，人以后就不敢点取消了 | — | 停在 C* |
| **F4** | 导出失败 | 顶部提示条（与「被权限拦下」同一处排版：宽 620 居中）：`导出失败：<系统给的原因>` + 右侧 `知道了` | `知道了`（清掉这条） | C* |
| **F5** | 复制成功 | 该按钮图标 `doc.on.doc` → `checkmark`，**1.5 秒后自动回复**；悬停提示同步变 `已复制到剪贴板`。它是**视图局部状态**、不进 `store`（只描述"这颗按钮刚被按过"） | 1.5 秒内可再点 | 1.5 秒后回 C* |

**关键判据：整理失败的会议也能导出（这是设计决定，不是漏了拦截）。**

`MeetingExporter.markdown` 只读会话数据、**不检查整理是否成功** → C4（材料不足）/ C6（模型未返回）/ C7（结果不完整）**全部可导出**，
内容是「已经拿到的部分 + 原文（逐字稿）附录」。整理失败时文首会引一句**真实原因**（`> ⚠️ 整理模型未返回…`）——
**这条必须留着**：不写的话，收件人会把「只有逐字稿」读成「这场会确实什么都没定」，那是一个**错误结论**，比缺内容更糟。
反过来，若连逐字稿也没有，导出的是一个只有元信息头的空壳 —— 目前**不拦**（「有会话就能导」比「替用户猜什么时候不该导」更可预期）。

⚠️ **缺口（本轮实测发现，未修）**：**D1（转写失败）没有导出入口**。导出与复制挂在结果页 Tab 栏上，
而 `.failed` 走的是 `WorkbenchFailureState`（只有 `重新处理` / `打开文件夹`），两者不共存。
后果：**部分转写**就失败的那场会（`transcriptSegments` 里已经有若干段）**目前拿不出去** —— 而它恰恰是"有内容、但状态是失败"的那一类。
不顺手补的原因：失败卡上没有 Tab 栏，要塞按钮就得先决定失败卡要不要长出第二个动作位；
且转写失败多数是「录音未启动」这种零内容情况，加了入口反而诱导用户导出一个空壳。**留作 v0.12 观察项**（先看真实使用里有没有人抱怨）。

## 二、状态遍历手法（用来验收「正确」，不靠用户眼睛）

**验收"落地"** = md5 / 测试 / 像素扫描（已有做法，保留）。
**验收"正确"** = **逐状态**渲染出来核对三列。逐状态而非逐轮次——一次会话覆盖 N 个状态，直接对冲「往返贵」。

### 夹具手法（按成本从低到高）

| # | 手法 | 适用 | 备注 |
|---|---|---|---|
| F-A | `.onAppear` 置状态 | B1~B5（进行中） | 最快，不改数据 |
| F-B | `@State` 初值 / 注入构造参数 | C4~C7、D1（空态、失败卡） | 纯渲染，最安全 |
| F-C | `MS_DATA_ROOT` + 临时夹具会话 | A1~A3、C1~C3、E1 | **用后对账**；绝不写真实根（给 store 开 `init(storage:)`，别靠环境变量） |
| F-D | `defaults write` | 设置面板（D3） | 只影响该面板 |
| F-E | **真实老数据**（常设夹具） | E1 + 每轮回归 | 唯一能证明"老会话仍可读"的夹具 |

### 硬约束（沿用既有纪律）

1. 夹具**不得包含真实会议数据**（脱敏或合成）。
2. 截完**还原并 `git diff` 复核**。
3. 交付时**写明「哪个动作本身没被实测」**。
4. `CGEvent` 注入的滚轮 / 点击**被静默丢弃** → 需要滚动才能看到的状态，用 `.defaultScrollAnchor(.bottom)` 一类最小夹具代替。
5. 判定用**像素值**（理论对比度常比像素实测高 0.3~0.5）。
