# 产品迭代计划 v0.11 —— 接上闭环

> 依据：`docs/产品方向调研报告-2026-09.md`（2026-09-16 已修正一版，见该文 §1.2 的「假阴性教训」）。
> 本计划只做**一件事**：把已经产出的东西送出去，并且让每一句话都能被核对。
> 状态：**待确认**（确认后即开工）。

---

## 0 这一步要解决什么

**Outcome（可测的一句话）**：

> 「一场会议录完，我**不做二次加工**就能把它发出去，而且每一句我都敢核对。」

**可量化口径**：从「录音结束」→「纪要到达目标位置」，**人工操作次数 ≤ 1 次**。

**为什么不是先优化纪要质量**：质量优化得再好，用户拿不出去也感知不到。
项目此前已投入阶段 0~4 一整套质量工程，质量确实上去了，**但产出仍困在 App 里** ——
这是「优化了过程，没优化结果」。

## 1 范围

### 做（5 个任务）

| 编号 | 任务 | 一句话 |
|---|---|---|
| **E1** | **导出 Markdown 文件** | 一场会 → 一个 `.md`，存到用户选的位置 |
| **E2** | **一键复制全文** | 一次点击，剪贴板里是完整纪要（发群里用） |
| **E3** | **跳转铺开到 5 处** | 点条目 → 跳到那段录音并开始播（要点锚已能跳，补齐其余） |
| **E4** | **逐字稿播放跟随** | 播放时当前句高亮 + 自动滚动 |
| **E5** | **状态表补齐 + 测试 + 验证** | 新状态进 `docs/状态表.md`，补单测，跑像素核验 |

### 不做（本版明确排除）

| 不做 | 为什么 |
|---|---|
| 导出 SRT 字幕 / `.ics` 日历 / 可勾选待办 | 没有需求信号，先看 E1/E2 有没有人真的用 |
| 导出 PDF / Word | Markdown 已能在飞书、腾讯文档、Notion 直接粘；加格式=加维护面 |
| 云端同步、协作、评论 | 与「内容不出机器」的地基正面冲突 |
| 3 人以上说话人分离 | 要引 Python 运行时，与纯本机 Swift 定位冲突，且无需求信号 |
| 改摘要 prompt / 提质量 | 本版不动质量侧；质量侧另有阶段（见调研报告 §6 第二步） |

## 2 任务拆解

### E1 导出 Markdown 文件

**新增 `MeetingExport.swift`**（纯函数，可单测；**必须同时加进 `Package.swift` 的 `sources` 白名单**）。

| 落点 | 内容 | 判据 |
|---|---|---|
| `MeetingExporter.markdown(for:)` | 整场导出：结论 → 要点 → 决策 → 待办 → 待确认 → 概述 → 经过 → 逐字稿（附录） | 纯函数，输入 `MeetingSession` 输出 `String` |
| `MeetingExporter.fileName(for:)` | `<日期>-<会议标题>.md`，**过滤 `/ : \\` 等文件名非法字符**，标题为空时退回「未命名会议」 | 含特殊字符的标题不产生非法文件名 |
| `MeetingExporter.appendixMarkdown(...)` | 逐字稿附录带 `[mm:ss]` 与说话人（有才写） | 无说话人时不写占位符 |

**为什么 Markdown**：`**加粗**` / `##` / `- [ ]` 在飞书文档、腾讯文档、Notion 里粘贴即渲染；
纯文本会丢掉层级，PDF/Word 会把「粘进文档再编辑」这条路堵死。

**Store 侧**（`MeetingStore.swift`）：新增 `exportSelectedSession()`，走 `NSSavePanel`
（`allowedContentTypes = [.plainText]`、默认文件名来自 `fileName(for:)`、写 UTF-8）。

**界面落点**：`WorkbenchResultTabBar.pageActions`（`WorkbenchView.swift:763`）加一颗
`doc.badge.arrow.up`；与既有「重新整理 / 打开文件夹」同排、同 `WorkbenchStripIconButtonStyle`。

> **成功不弹提示**——SavePanel 自己关掉就是成功，这是 macOS 惯例。
> **失败要给可读文案**（磁盘满 / 无写权限），复用既有的 `WorkbenchInlineNotice`。

### E2 一键复制全文

| 落点 | 内容 |
|---|---|
| `MeetingStore.copySelectedSessionToPasteboard()` | 把同一份 markdown 写进 `NSPasteboard.general` |
| 工具栏按钮 | `doc.on.doc`，紧挨导出 |
| 点击反馈 | 图标临时切成 `checkmark`（1.5s 后回退），**不新增全局状态** |

**判据**：复制后 `pbpaste` 的内容与 `MeetingExporter.markdown(for:)` 逐字节一致。

### E3 跳转铺开到 5 处

**已经有的**：`WorkbenchOverviewBulletsSection`（要点锚）→ `onJump` → `jump(to:)`
（`WorkbenchView.swift:911 / 1034`，逻辑是「先 seek、没在播就开播」）。

**缺的 5 处**（都已定位到行）：

| # | 渲染点 | 行 | 跳转目标 |
|---|---|---|---|
| 1 | `WorkbenchTimelineDocumentRow`（速览·经过） | `:974` | `TimelineChunk.start` |
| 2 | `WorkbenchOverviewSummaryRow`（速览·决策/待办摘要） | `:1021` | 对应 `timestamp` |
| 3 | `WorkbenchDecisionDocumentRow`（纪要·决策） | `:1384` | `InsightItem.timestamp` |
| 4 | `WorkbenchActionDocumentRow`（纪要·待办） | `:1404` | `ActionItem.timestamp` |
| 5 | `WorkbenchTranscriptDocumentRow`（原文·逐字稿） | `:1468` | `TranscriptSegment.start` |

**三条纪律**（沿用现有实现的做法，别各自发明）：

1. **`timestamp` 为 nil 时锚退化成纯文字**，不做成「点了没反应的按钮」；
2. **音频不可用（`player.isAvailable == false`）时全部退化**——判据同现有 `:911`；
3. **时间戳从 `String` 改成可点**：`WorkbenchDocumentItemRow` 现在收的是 `time: String?`，
   要改成一个可选回调参数（**默认 nil**，这样调用点不传就是纯文字，行为不变）。

### E4 逐字稿播放跟随

| 落点 | 内容 | 判据 |
|---|---|---|
| `MeetingTranscript.currentSegmentIndex(at:in:)`（纯函数） | 给 `currentTime` 找当前段 | **单测**：0 秒 / 段间空隙 / 末尾 / 空数组 四种边界 |
| 原文页包一层 `ScrollViewReader` | 当前段变化时 `scrollTo(id, anchor: .center)` | 播放时不手滚，当前句持续在视野内 |
| 当前段高亮 | 仅换**底色**，不动字号字重（避免行高跳动） | 高亮不引起重排 |

> ⚠️ **这一个是本版唯一有回归风险的改动**：正文 `ScrollView`（`:593`）目前用**普通 `VStack`、
> 非懒加载**（逐字稿最多一千多段）。加 `ScrollViewReader` + 每 0.25s 一次的 `scrollTo`
> 可能带来滚动卡顿或「拽不动」。
> **降级预案**：若实测卡顿，则去掉自动滚动、只保留高亮 + 播放条上一个「跳到当前句」按钮。

### E5 状态表补齐 + 测试 + 验证

| 动作 | 内容 |
|---|---|
| `docs/状态表.md` 新增状态 | **导出中 / 导出成功 / 导出取消 / 导出失败 / 复制成功** 五态的「显示什么字·能点什么·点了去哪」 |
| 状态表要回答的问题 | **整理失败的会议能不能导出？** → 应当能（逐字稿还在），需在表里写死 |
| 新增单测 | `MeetingExportTests`（文件名清洗 / 空标题 / 逐字稿附录 / 无时间戳条目）+ 播放跟随定位函数 |
| 验证 | `swift test` 全绿 → 打包 → **像素/OCR 核验**（工具栏多两颗按钮后，标题栏不能被挤折行） |

## 3 验收标准（可判定，不写「感觉更好」）

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | 导出的 `.md` 粘进**飞书文档 / 腾讯文档 / Notion** 格式不乱 | 人工各粘一次，看标题层级与列表 |
| 2 | 复制内容与导出文件**逐字节一致** | `pbpaste` vs 文件 `diff` |
| 3 | 点**任意**有时间的条目都能跳并开始播 | 5 处各点一次 |
| 4 | **没有时间戳**的条目是纯文字、不是死按钮 | 造一条无 timestamp 的数据看渲染 |
| 5 | 音频不可用时**5 处全部**退化 | 删掉音频文件再看一遍 |
| 6 | 播放跟随时当前句高亮且自动进视野 | 播放 30 秒不手滚 |
| 7 | 标题栏按钮**没被挤成两行** | 像素核验（本项目已栽过：工具栏会收成一组 + 折行） |
| 8 | 单测与既有 206 条**全部通过** | `swift test` |

## 4 风险与前提

| 风险 | 应对 |
|---|---|
| **标题栏被挤折行** | 已栽过（工具栏同一 placement 会被收成一组、间距被系统压到 1pt）。两颗新按钮**放进同一个 `HStack`**，label 加 `.lineLimit(1)` + `.fixedSize()`，并用像素核验 |
| **`WorkbenchDocumentItemRow` 签名变更波及调用点** | 新增参数**给默认值 nil**，调用点不改也编译通过、行为不变 |
| **播放跟随导致滚动卡顿** | 见 E4 降级预案 |
| **导出内容与界面不一致** | 导出**复用同一份数据**（`session.analysis` / `transcriptSegments`），不另建一份渲染逻辑 |
| **中文文件名** | `NSSavePanel` 默认文件名走 `fileName(for:)`；注意 zip/传输场景下的编码（本项目已知 `ditto` 打包中文名正常） |

**前提**：不改存储模型（**不加字段**）→ 本版**没有老会话兼容问题**，这是刻意选的。

## 6 确认点（需要你拍板的三件事）

| # | 问题 | 我的建议 |
|---|---|---|
| 1 | **导出格式**：只做 Markdown，还是同时给纯文本？ | **只做 Markdown** —— 纯文本会丢层级，且两条路维护成本翻倍 |
| 2 | **导出范围**：整场一个文件，还是按页（速览/纪要/原文）分别导？ | **整场一个文件**（逐字稿做附录）—— 发出去的是「一份纪要」，不是三份 |
| 3 | **播放跟随的取舍**：卡顿时宁可去掉自动滚动、只留高亮吗？ | **是** —— 高亮零风险，自动滚动是加分项不是刚需 |
